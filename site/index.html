placeswiki is an open-source dataset of historical places and landmarks — coordinates, descriptions and photographs — assembled from Wikidata and Wikimedia Commons, and served in the protocol of the Google Places API.

Places APIs are metered twice: each lookup is billed, and the terms forbid keeping what you fetched. The same facts — a church, its coordinate, forty photographs of it — are already published by volunteers under licences that permit redistribution.

placeswiki builds that database once, stores it in a single SQLite file, and answers the Google endpoints from it. Your client changes one base URL and keeps its parser. Everything runs on hardware you control: no account, no key, no per-request fee.

Install

Two commands to a working endpoint. Docker is the shortest path.

Build and run

docker build -t placeswiki .
docker run -d -p 8080:8080 -v "$PWD/data:/data" placeswiki

Or from PyPI

pip install placeswiki
placeswiki bulk fetch --db data/places.sqlite --country Q215
placeswiki serve --db data/places.sqlite --port 8080

Python 3.9+, standard library only. Deployment recipes for Caddy, nginx, systemd, Fly.io and Render are in the deployment guide.

Use it

The endpoints are Google's; so are the field masks and the error envelopes.

const BASE = "https://places.yourdomain.com";

await fetch(`${BASE}/v1/places:searchNearby`, {
  method: "POST",
  headers: { "X-Goog-FieldMask": "places.id,places.displayName,places.location" },
  body: JSON.stringify({
    locationRestriction: { circle: { center: { latitude: 46.05, longitude: 14.5 }, radius: 500 } }
  })
});

POST /v1/places:searchNearby · POST /v1/places:searchText · GET /v1/places/{id} · GET /v1/{photo_name}/media. Field masks, 20-result caps and error envelopes behave as they do upstream. Guides: integration and API.

The data

Wikidata records about 2.2 million heritage-designated places with coordinates. Each is staged, enriched with its Commons photograph, and given a stable identifier of the form wc:Q10285. Google place identifiers are attached only as an optional join key, never as the primary identity.

Photographs are scored rather than picked at random — resolution, licence, attribution, and whether the community chose it as the lead image — and the reasons are stored beside the score.

A 500-place sample from Slovenia ships with every release: 500 places, 377 photographs, 336 KB including the attribution file.

Community

This is an open-source project in the ordinary sense: MIT code, a public repository, and decisions made in issues rather than in private. There is one maintainer and no company behind it.

Use it, break it, report it

Open an issue with the command and what happened. Bugs in the crawler, the schema or the served protocol are all fair game.

Send a pull request

Tests run offline, the standard library is the only runtime dependency, and no scraper is accepted. Read CONTRIBUTING.md first; it is short.

Fix the data upstream

A wrong coordinate is wrong in Wikidata; a missing author is missing on Commons. placeswiki gaps lists what is absent, with links to the items that need work.

Discussion happens in Discussions; releases are tagged and downloadable from Releases.
