    placeswiki is an open-source dataset and server for historical places and landmarks. It collects coordinates, descriptions and photographs from Wikidata and Wikimedia Commons, and answers the endpoints of the Google Places API from a single SQLite file.[1]

    Its purpose is to remove a per-request cost from applications that display heritage sites. Google's Places API is billed per lookup and its terms restrict storing what is retrieved;[2] the same facts are published by volunteers under licences that permit redistribution.

    Background

    Places data is metered twice. Each lookup is billed, and the Google Maps Platform Terms of Service forbid exporting or storing Places content outside the service except for place identifiers, which may be kept indefinitely.[2] The cost therefore does not fall as an application grows, and the data cannot be amortised.

    Wikidata holds roughly 2.2 million items with a heritage designation (P1435) and coordinates (P625); Wikimedia Commons holds their photographs under per-file licences.[3] Neither corpus is complete, but both are redistributable and machine-readable.

    Design

    The system has four stages, each resumable and none writing to Wikimedia:

    • Acquire — crawl Wikipedia by category, by link graph, or by a geographic grid that survives the API's 500-result cap; or stage the Wikidata list in bulk.
    • Identify — resolve each article to a Wikidata item and store a stable wc:Q… identifier. Google identifiers are attached later, as an optional join key.
    • Enrich — resolve Commons images with their author and licence, then score them for resolution, licence, attribution and whether the community chose them as the lead image.[4]
    • Serve — answer Nearby Search, Text Search and Place Details from a slim read-only database, including field masks and a media endpoint that resolves photographs.

    Data

    Two city samples ship with the page: Berlin (1,600 places, 1,297 photographs) and São Paulo (991 places). Berlin's landmark query matches 9,242 places — heritage listings plus bridges, parks, squares, monuments and other landmarks, with restaurants, shops and hotels excluded — but enrichment is rate-limited by Wikidata, so the page ships the first 1,600.

    The search box works in the same order the data is built: pick a city, then search the places inside it. Both indexes are static JSON, fetched only when used.[3] Photographs remain under their own licences and are attributed per file, in the bundle's ATTRIBUTION.md.

    Adoption

    The server speaks the Places API (New) protocol, so a client changes one base URL and keeps its parser.[1]

    docker build -t placeswiki .
docker run -d -p 8080:8080 -v "$PWD/data:/data" placeswiki

curl -X POST localhost:8080/v1/places:searchNearby \
  -H "X-Goog-FieldMask: places.id,places.displayName,places.location" \
  -d '{"locationRestriction":{"circle":{"center":{"latitude":46.05,"longitude":14.5},"radius":500}}}'

    Deployment recipes for Caddy, nginx, systemd, Fly.io and Render are in the repository; the image runs unprivileged and exposes /health.

    Community

    The project is maintained in public. Code is MIT-licensed; tests run offline; no scraper is accepted, because services such as Google Maps forbid it and importing their data would compromise every downstream user.[2]

    Data corrections belong upstream. A wrong coordinate is wrong in Wikidata, and a missing author is missing on Commons; the gaps command lists what is absent with links to the items that need work.[3]

    Licence

    Code is released under the MIT licence. Text derived from Wikipedia is CC BY-SA 4.0; photographs keep their own licences. Google place identifiers remain subject to Google's terms. Fields generated by this project — identifiers, inferred types, match scores — are released CC0.[5]
